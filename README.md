# BUSINESS STAND — сайт и админ-панель

Сайт компании BUSINESS STAND: проектирование, производство и застройка выставочных стендов,
с админ-панелью для проектов, главной страницы, услуг, данных компании и заявок.

Сайт на [Astro](https://astro.build) в серверном режиме (Node.js). Контент хранится в базе SQLite
(встроенный в Node модуль `node:sqlite`), загруженные изображения — на диске рядом с ней.

## Требования

- **Node.js 24** или новее: нужен встроенный SQLite и запуск `.ts`-скриптов без сборки.
- Постоянный диск для папки данных (`DATA_DIR`). Хостинги без постоянного диска и
  «бессерверные» платформы (Vercel, Netlify Functions, Cloudflare Pages) не подходят:
  база и фото пропадали бы при каждом развёртывании.
- **Один процесс сервера.** SQLite рассчитан на один процесс записи, поэтому не запускайте
  несколько копий сайта на одну папку данных.

## Быстрый старт (разработка)

```bash
npm install
npm run admin:create -- --email you@company.ru   # спросит пароль (не короче 12 символов)
npm run dev                                       # http://localhost:4321, админка: /admin
```

При первом запросе пустая база заполняется исходным контентом сайта (тексты из `src/data/ru.ts`,
шесть проектов-примеров, шесть услуг и фото из `src/assets/images`). Это занимает 10–15 секунд
один раз. Существующая база никогда не перезаписывается.

## Развёртывание на сервере

```bash
npm ci
SITE_URL=https://ваш-домен.ru npm run build      # SITE_URL нужен именно при сборке
npm run admin:create -- --email you@company.ru
DATA_DIR=/var/lib/business-stand HOST=127.0.0.1 PORT=4321 TRUST_PROXY=true npm start
```

- Перед сервером поставьте nginx или Caddy с HTTPS. Cookie входа передаются только по HTTPS
  (на `localhost` — и по HTTP, для разработки).
- `npm start` запускает `dist/server/entry.mjs`. Держите процесс под systemd или pm2,
  рабочая папка — корень проекта (оттуда при первом запуске берутся исходные фото).
- Для загрузки файлов увеличьте в прокси предел размера запроса до 25 МБ
  (nginx: `client_max_body_size 25m;`).

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `SITE_URL` | Боевой адрес сайта. Нужен **при сборке**: canonical-ссылки, превью в соцсетях и защита форм от подделки (домен из него считается «своим»). |
| `ALLOWED_HOSTS` | Дополнительные имена сайта через запятую, например `www.ваш-домен.ru`. |
| `DATA_DIR` | Папка с базой, фото, вложениями заявок и резервными копиями. По умолчанию `./data`. |
| `HOST`, `PORT` | Адрес и порт сервера для `npm start`. |
| `TRUST_PROXY` | `true`, если перед сайтом прокси, который выставляет `X-Forwarded-For`: тогда ограничения частоты считаются по посетителям, а не по адресу прокси. Включайте только за прокси. |
| `COOKIE_SECURE` | `false` отключает флаг Secure у cookie — только для локальной сети без HTTPS. |
| `TZ_DISPLAY` | Часовой пояс дат в админке, по умолчанию `Europe/Moscow`. |

Секретов в коде нет: пароль администратора задаётся командой `admin:create` и хранится только
в виде хеша scrypt.

## Админ-панель

Вход: `/admin/login`. Разделы:

| Раздел | Что там |
| --- | --- |
| `/admin` | Обзор: число проектов, новые заявки, неопубликованные черновики, последние действия. |
| `/admin/projects` | Все проекты с поиском, фильтрами по статусу и формату и сортировкой. |
| `/admin/projects/new`, `/admin/projects/:id` | Тексты проекта, адрес страницы, детали, SEO, галерея, публикация, история текстов, предпросмотр. |
| `/admin/homepage` | Первый экран, три карточки, заголовки разделов, **галерея «Наши проекты» на главной** (какие проекты и в каком порядке), блок контактов, SEO. |
| `/admin/about` | Разделы «Наш подход» (этапы) и «Почему мы» (в меню сайта — «О компании»). |
| `/admin/services` | Услуги: порядок, показ на сайте, тексты, изображение. |
| `/admin/media` | Медиатека изображений для главной и услуг. |
| `/admin/requests` | Заявки, сохранённые до перехода на отправку по почте (новые приходят на businesstend@yandex.ru). |
| `/admin/settings` | Данные компании (контакты), пароль, активные входы, резервные копии. |

**Черновики.** Главная, «О компании» и данные компании редактируются как черновик: «Сохранить черновик»
не меняет сайт, «Предпросмотр» показывает страницу с черновиком, «Опубликовать» выкладывает его.
Каждая публикация попадает в историю, любую прошлую версию можно загрузить обратно в черновик.
Проекты сохраняются сразу, но видны посетителям только в статусе «Опубликован»; у каждого
сохранения текстов есть версия, которую можно вернуть.

**Галерея проекта.** Загрузка нескольких фото с прогрессом, порядок перетаскиванием или стрелками,
выбор обложки, описания фото, удаление с подтверждением. Каждое действие — отдельный запрос:
страница не перезагружается и не прокручивается, несохранённые тексты проекта остаются в форме.

**Заявки по почте.** Каждая заявка с формы сайта уходит письмом на **businesstend@yandex.ru**
(`src/server/mail.ts`): поля заявки, прикреплённый бриф, «Ответить» — на почту клиента. На сайте и в
админке заявки не сохраняются. Посетитель видит «Заявка отправлена» только после того, как почтовый
сервер принял письмо; иначе — сообщение, что заявка не отправлена, и совет написать в мессенджер.
Защита от спама: скрытое поле-ловушка и не больше 5 заявок за 10 минут с одного адреса.

Чтобы отправка заработала, на сервере задайте переменные окружения (пример — в `.env.example`):
`SMTP_USER` и `SMTP_PASS` — ящик, с которого сайт отправляет письма, и его пароль. Для Яндекс Почты
нужен **пароль приложения** (Яндекс ID → Безопасность → Пароли приложений → «Почта») и включённый в
настройках ящика доступ почтовых программ. По умолчанию — `smtp.yandex.ru:465` (SSL), отправитель —
сам ящик (`MAIL_FROM`), получатель — businesstend@yandex.ru (`INQUIRY_TO`). Пароль хранится только на
сервере и в браузер не попадает. Без этих настроек форма честно сообщает, что заявка не отправлена,
а в журнале сервера появляется строка `[inquiry] not sent`.

Раздел админки «Заявки» остался для заявок, сохранённых раньше; новые туда не попадают.

## Безопасность

- Пароли — scrypt с солью; вход блокируется на 15 минут после 5 неудачных попыток на учётную запись
  (и 20 — с одного адреса).
- Сессия — случайный токен в cookie `HttpOnly`, `SameSite=Lax`, `Secure` (по HTTPS); в базе хранится
  только его хеш. Сессия истекает через 12 часов бездействия или 7 дней. Смена пароля завершает
  остальные входы.
- Все изменяющие запросы админки требуют CSRF-токен сессии; формы с чужих сайтов отклоняются
  проверкой Origin.
- Все поля проверяются на сервере. Тексты выводятся с экранированием, HTML из админки не вставляется.
- Изображения декодируются и перекодируются (метаданные, в том числе GPS, удаляются), имена файлов
  генерируются сервером. Фото неопубликованных проектов видит только администратор.
- Вложения заявок проверяются по расширению и сигнатуре файла и отдаются только на скачивание.
- Ответы админки: `Cache-Control: no-store`, `X-Frame-Options: DENY`, `noindex`, Content-Security-Policy.

## Данные, резервные копии и восстановление

Всё в `DATA_DIR`:

```
site.db         база SQLite (режим WAL)
media/          изображения: для каждого — WebP 480–2400 px, миниатюра и картинка 1200×630 для соцсетей
attachments/    вложения заявок
backups/        резервные копии
```

```bash
npm run backup                         # копия базы, фото и вложений; можно на работающем сайте
npm run restore -- --list              # список копий
npm run restore -- <имя копии>         # остановите сайт перед восстановлением
```

В админке копию можно создать в «Настройках». Хранятся последние 14 копий. **Регулярно копируйте
папку `backups/` на другой носитель**, например ежедневно по cron: `npm run backup && rsync …`.
При восстановлении текущие данные не удаляются, а переносятся в `DATA_DIR/replaced-<дата>`.

**Схема базы и миграции.** Схема описана нумерованными миграциями в `src/server/migrations.ts`.
Номер применённой хранится в `PRAGMA user_version`. При старте недостающие миграции применяются
автоматически, а перед этим создаётся копия базы `site.db.before-migration-N-…`. Чтобы изменить
схему, добавьте новую миграцию в конец списка; уже выпущенные миграции не редактируются.
База новее кода не открывается.

## Проверки и тесты

```bash
npm run check       # типы и шаблоны
npm test            # модульные тесты серверной части (node:test)
npm run test:http   # сборка и тесты HTTP: доступ, CSRF, публикация, черновики, заявки
npm run test:e2e    # браузерный регрессионный тест галереи (после npm run build)
```

`test:e2e` запускает установленный Chrome через `playwright-core` (браузеры не скачиваются;
другой браузер — через `CHROME_PATH`). Он проверяет, что загрузка, перестановка
(перетаскиванием и стрелками), смена обложки и удаление фото не перезагружают страницу,
не сдвигают прокрутку и не стирают несохранённые название и описание проекта, а порядок
сохраняется на сервере.

## Что нужно заменить реальными данными

Все поля, которые компания ещё не подтвердила, показываются на сайте пунктирной рамкой.
Теперь их заполняют в админке:

- **Контакты** — телефон, почта, адрес, Telegram, VK: «Настройки» → «Данные компании».
- **Проекты** — шесть проектов из исходного контента помечены как «Пример формата»:
  клиент, выставка, площадь и год пустые, фото стоковые. Замените их реальными кейсами и снимите
  галочку «Пример формата».
- **Фотографии** — исходные изображения взяты с Unsplash (лицензия Unsplash License, ссылки
  на источники — в `src/data/images.ts`). Это иллюстрации, а не работы компании.
- **Персональные данные** — политика (`/privacy/`, `src/pages/privacy.astro`) и отдельное согласие
  (`/consent/`, `src/pages/consent.astro`; отдельным документом — требование ч. 1 ст. 9 152-ФЗ с 01.09.2025).
  Тексты описывают только то, что сайт делает на самом деле. Сведения, которые может дать только компания,
  заполняются в `src/data/legal.ts`; пустые поля на сайте не выводятся. Перед запуском заполните там:
  полное наименование, ИНН, ОГРН, адрес, почту для обращений, ответственного за обработку данных, место
  размещения сервера (база должна быть в России, ч. 5 ст. 18), лиц, обрабатывающих данные по поручению
  (например, хостинг), отсутствие трансграничной передачи (`crossBorderTransfer: false`), срок хранения
  заявок и дату редакции. Почта, телефон и адрес из «Настроек» тоже выводятся как способы связи.
  Подайте уведомление об обработке в Роскомнадзор (ст. 22) и согласуйте тексты с юристом.
- **Логотип в шапке** — видео `public/logo/business-stand-logo.mp4` с анимацией по прокрутке
  (`src/components/ScrollLogo.astro`). Само видео сайт не загружает: из него собираются кадры.
  После замены видео пересоберите их: `python3 scripts/logo-frames.py` (нужен Python 3 с Pillow и ffmpeg;
  на macOS без ffmpeg кадры читает `scripts/video-frames.swift`, нужны Xcode Command Line Tools).
  Если у нового ролика другое положение или размер знака, обновите замеры `MARK_CENTRE`, `MARK_HALF`
  и радиусы кольца в начале скрипта.
- **Логотип в подвале и иконка сайта** — временный знак в `src/components/Logo.astro` и `public/favicon.svg`.

## Автономная копия сайта (один HTML-файл)

```bash
npm run build && npm run export:html     # создаёт BuSt.html в корне проекта
```

`BuSt.html` открывается прямо с диска, без сервера: внутри все публичные страницы (главная, каталог,
опубликованные проекты, политика, 404), стили, шрифты, фото и кадры логотипа. Переходы между страницами
работают через адрес вида `#/projects/…`. Берётся только опубликованный контент; админки в файле нет.
Форма заявки в этой копии ничего не отправляет и прямо сообщает об этом. После изменений в админке
файл нужно собрать заново.

## Структура

```
src/
  server/          серверная часть без зависимостей от Astro: база, миграции, вход и сессии,
                   проекты, изображения, черновики, услуги, заявки, резервные копии
  middleware.ts    защита /admin и /api/admin, CSRF, заголовки безопасности, контент для страниц
  pages/           сайт (главная, /projects/, страницы проектов, политика, 404),
                   админка (/admin/…), API (/api/admin/…, /api/inquiry), отдача фото (/media/…)
  components/      секции сайта; components/admin — части админки
  scripts/admin/   браузерные скрипты админки (галерея, черновики, медиатека)
  layouts/         каркасы сайта и админки
  data/            тексты интерфейса и исходный контент для первого заполнения базы (ru.ts)
  styles/          дизайн-токены сайта и стили админки
scripts/           admin:create, backup, restore, сборка кадров логотипа
tests/             unit, http, e2e
```

## Английская версия

Тексты интерфейса (кнопки, подписи, сообщения формы) лежат в `src/data/ru.ts`. Для английской версии
нужны `src/data/en.ts` с той же структурой и страницы в `src/pages/en/`, а контент из админки
придётся хранить на двух языках — это отдельная доработка схемы базы (новая миграция).
